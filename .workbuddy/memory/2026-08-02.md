## 10 条改进实施 + 构建/测试验证（续）

逐个落地了上述 10 个方向并完成构建与测试验证。关键纠正与坑：

### 构建/类型修复（关键）
- **TS2305（`database` 包）**：`src/schema.ts` 是旧的前向文件，只 re-export `initializeSchema/migrateSchema` 而漏了 `migrations`；而 NodeNext 下 `database/index.ts` 的 `import ... from './schema.js'` 解析到文件 `schema.ts` 而非目录 `schema/index.ts`，导致 `migrations` 找不到。修复：`schema.ts` 桶文件补全 re-export `migrations`（schema/index.ts 为真实实现，单一真相源不变）。
- **AnyDB 决策**：曾把 `Kysely<AnyDB>` 的 `AnyDB` 从 `any` 改为 `Record<string, Record<string, unknown>>`，结果 achievements/auth/posts/teams/boards/admin 全部报错（`.select('col')`、`.where('col',..)`、`.set(eb=>eb('col','=',v))`、`.get<T>()/all<T>()` 的 `unknown→Row` cast 失效）。根因：未类型化 kysely 数据库下 `any` 是官方推荐的「非类型安全」用法，强约束为 Record 得不偿失。**最终沿用 `any`**，真实类型收益落在适配器层（LibSQLAdapter/KyselyAdapter 显式类型化 Client/Row/InArgs/PreparedStatement/RunResult + `as InArgs` 断言）。
- **teams/guards.ts TS2305**：从 `@campus-forum/core` 导入 `FastifyRequest/FastifyReply`，但 core 未导出这两个类型。修复：core/index.ts 新增 `export type { FastifyRequest, FastifyReply } from 'fastify'`（fastify 已在 core devDeps）。
- **server TS18046**：全局错误处理 catch 块误用 `error.message`（`error: unknown`），改为已收窄的 `err.message`（`const err = error as any`）。

### 构建基础设施（重要，跨会话复用）
- **不要**用 `npx tsc` 或 `node_modules/.bin/tsc`：git-bash 会把 `.bin/tsc` 符号链接路径损坏为 `D:\d\...`（双盘符），报 MODULE_NOT_FOUND。正确做法：`node "D:/Projects/campus-forum/node_modules/typescript/bin/tsc"`（Windows 风格带冒号路径 MSYS 不会二次转换）。
- **server / core 构建需内存**：Fastify 类型图过大，普通 tsc 会 `Fatal process out of memory`（exit 3/134）。加 `NODE_OPTIONS=--max-old-space-size=4096`。
- `rm`/`rm -rf` 被 safe-delete 守卫拦截（git-bash `/d/...` 路径被当成相对路径拒绝）；清理产物请用其他方式或显式绝对 Windows 路径。
- vitest 收尾会 hang（server 不关闭），但结果已先打印；重定向到日志读取即可，勿空轮询。
